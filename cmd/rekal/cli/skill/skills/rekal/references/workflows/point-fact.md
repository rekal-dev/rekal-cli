# Pointed ledger workflow

Use this lens for a fact, episode, explanation, provenance, reflection, or other
ledger answer not covered by the higher-priority answer types.

**Evidence contract**

- For a fact, the requested actor, entity, relation, semantic slot, and time
  scope stay fixed while candidates are judged.
- For a why, provenance, or decision arc, causal claims need explicit steering,
  correction, or "because" evidence; a chronological sequence alone is not a
  reason.
- Discussed is not owned, suggested is not chosen, planned is not completed,
  another speaker's fact is not the actor's fact, and an adjacent event is not
  the requested event.
- Later corrections or state changes matter when the answer asks for current or
  latest state. Contradicted premises remain false.

Useful operations include recalling then drilling the assertion turn, or loading
`references/ledger.md` for deeper decision-arc, reflection, and analytical SQL.
When retrieved evidence signals that an exact fact may be buried, one focused
reformulation using a stable entity, synonym, or relation can test that signal.

If the focused evidence remains weak, preserve the gap rather than selecting the
closest fact. Answer only what was requested at the record's precision.
